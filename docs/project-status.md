# 프로젝트 기준과 미결정 사항

2026-10-12에 확인한 요구사항 정의서와 SAD v0.1 초안을 기준으로 정리했습니다.
이 문서는 개발 상태와 설계 차이를 기록하며 원본 문서를 대체하지 않습니다.

| ID | 요구사항 | 현재 저장소 상태 |
|---|---|---|
| FR-01 | 시선 방향과 사전 등록 IoT 대상 식별 | 인식 함수 TODO |
| FR-02 | 3종 이상 손동작 인식과 명령 매핑 | 매핑만 구현, 인식 TODO |
| FR-03 | 시선과 손동작을 조합한 의도 판단 | 기본 결합·신뢰도·시간 검사 구현, 유지 시간과 상태머신 TODO |

| NFR-03 | 불필요한 원본 장기 저장 방지, 접근 제한 | 현재 영상 저장 코드 없음, 서버 인증·인가 TODO |

## 팀에서 결정할 사항

- SAD의 FR-01/03/04 이름이 정의서와 다릅니다. 요구사항 번호는 위 표에 맞춰 수정해야 합니다.
- 정의서는 시선으로 대상 선택을 요구하지만 SAD는 손가락 포인팅도 허용합니다. 대체 입력 허용 여부를 결정해야 합니다.
- 정의서의 도움 요청은 시선·제스처 조합이고 우선순위는 중입니다. SAD에는 단독 HELP 제스처 및 우선순위 낮음이라는 다른 내용이 있습니다. 현재 코드는 정의서를 기준으로 합니다.
- 실행 역할별로 edge(카메라), server(AI·의도 판단·API), firmware(ESP32), web(보호자), shared(공통 형식)로 코드를 분리했습니다. Pi 영상 전송, 서버 추론 연결, MQTT·ESP32 제어는 아직 구현되지 않았습니다. 기존 로컬 통합 실행은 scripts/local_demo.py에서 유지합니다.
- 시선 좌표와 실제 기기 위치를 연결하는 보정 방법, 사용자 위치 조건, 제스처 유지 시간을 정해야 합니다.
- 2초 성능 측정의 시작·종료 시점과 재전송 시간을 포함할지 정해야 합니다.

SAD에 적힌 FastAPI·MediaPipe·AWS·MQTT·PostgreSQL·Redis 등은 설계안이며,
현재 저장소에 해당 기능이 모두 구현되어 있다는 의미는 아닙니다.

3. 분리한 edge와 server 사이의 영상 전송, 서버와 ESP32 사이의 MQTT 기기 제어 연결
4. 보호자 알림 저장·인증·처리 상태 구현
5. 실제 장비에서 정확도, 오작동, 응답 시간 측정
